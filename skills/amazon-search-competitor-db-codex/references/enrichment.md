# 来源明确的资料补齐

## 公司与地址

卖家ID优先本次目标商品/自然卡片的Buy Box证据，缺项才用第三方。第三方卖家ID与本次不同时，不能套旧卖家名称、国家、公司或配送。

先取Amazon卖家页Business Name/Address。页面不可得时可用按ID精确查询的Sorftime等明确公司名/地址字段写入公司地址（Z）和公司主体（AD），标第三方及未直接核实；不要把已取得的可追溯资料仅留说明导致主表大量空白。字段provenance.source_type=third_party_database，生成器标浅黄。

品牌、店铺、公司不是同一概念。只有sellerNation不能推断公司。Amazon自营无正式主体/地址证据则留空。按明确国家字段译中文；美国州CA等不能误当其他国家。代码与明确地址国家冲突时留空并记证据。

卖家ASIN数量可用工具报告店铺总商品数，说明计数粒度是否已知；样本内数量须明示。卖家最佳自然排名取当前主表同卖家ID的最小排名，注明样本口径。

## FBA配送费、包装尺寸与包装重量

这三列只来自 Sorftime `product_detail`，每个确切ASIN扣1点。取 `fba_fee`、包装尺寸（厘米）和包装重量（克），原样写入，不把英寸或磅换算进来，也不用同类商品、父体或页面猜测。

| 主表列 | 接口字段 | 写入规则 |
|---|---|---|
| FBA配送费（L） | fba_fee | 美元数字。空、非数字或负数写 null |
| 包装尺寸(cm)（M） | 包装尺寸 | 文本「长 × 宽 × 高」，单位厘米。任一边缺失写 null |
| 包装重量(g)（N） | 包装重量 | 克的整数部分。空、非数字或负数写 null |

按确切ASIN合并。缓存放在本次任务工作目录的 `sorftime_cache.json`，键就是ASIN，不要写死某台机器的绝对路径。多个搜索词可以共用同一个任务目录里的这份缓存。

```json
{
  "B0EXAMPLE01": {
    "fba_fee": 3.21,
    "package_size_cm": [10, 5, 3],
    "weight_g": 120
  }
}
```

先读缓存。只有没有该ASIN记录时才调用 `product_detail`。成功后写入临时文件再 rename，避免写到一半被下一次读取。同一ASIN不第二次扣点。接口没有返回的字段保持 null，并在说明里记缺口。

## 日期、销量及缺失

availableDate可作注明来源的第三方上架日，createdTime不能代替。最早返回历史记录可能只是窗口起点；不能证明上架日时保留未知。确用近似日时标 `_listing_date_approx: true`，不伪称真实。上架时间写入K列，只保留日期。

页面购买量带+仅为下限。估算只有周期、粒度明确匹配目标ASIN才补主表；父体或同父相同units留副表/证据，不当子体销量。估算销量的浅橙只涂I列近一月销量，包装重量（N）和其他列不加这层颜色。

AA列卖家精灵数据更新时间继续用真实 `updatedTime`。生成器把它换到北京时间后只留日期，不保留时分秒，也不用查询时刻填空。

空值不是补查结束的理由，应尝试已授权且合适的来源并记录真实缺口；同时不能为了消除空白编造事实。交付报告覆盖及来源性质，而非只说33列已完成。库存状态为「无购买框」时，价格留空。
